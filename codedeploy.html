What is AWS CodeDeploy?

AWS CodeDeploy is a fully managed deployment service that automates software deployments to various compute services.

Key Benefits

  • Automated Deployments: Eliminates manual deployment steps and errors
  • Minimize Downtime: Progressive deployment strategies reduce risk
  • Automatic Rollback: Reverts to previous version when issues detected
  • Centralized Control: Manage deployments across multiple environments

Supported Compute Platforms

  • ✅ AWS Lambda
  • ✅ Amazon ECS
  • ✅ Amazon EC2
  • ✅ On-premises servers

Focus: Lambda Functions

Canary Deployment Strategy

Canary10Percent5Minutes

Gradually shifts traffic from old version to new version, allowing early detection of issues.

How It Works

  • Phase 1 (0 min): 10% traffic → New version | 90% traffic → Old version
  • Monitor: Watch CloudWatch alarms for 5 minutes
  • Phase 2 (5 min): If healthy → 100% traffic → New version
  • Rollback: If alarm triggers → Revert to old version immediately

Traffic Shift Timeline

T+0 min: 🟢🟢🟢🟢🟢🟢🟢🟢🟢🔴 (10% new version)

T+5 min: ⏱️ Monitoring period (CloudWatch alarms checked)

T+5 min: 🔴🔴🔴🔴🔴🔴🔴🔴🔴🔴 (100% new version)

On Alarm: 🟢🟢🟢🟢🟢🟢🟢🟢🟢🟢 (Rollback to old version)

💡 Why Canary? Limits blast radius - only 10% of users affected if there's an issue!

CDK Implementation (1/3)

Lambda Function & Alias Setup

import * as lambda from 'aws-cdk-lib/aws-lambda'; import * as codedeploy from 'aws-cdk-lib/aws-codedeploy'; import * as cloudwatch from 'aws-cdk-lib/aws-cloudwatch'; // Create Lambda function const apiFunction = new lambda.Function(this, 'ApiFunction', { runtime: lambda.Runtime.NODEJS_20_X, handler: 'index.handler', code: lambda.Code.fromAsset('lambda'), environment: { STAGE: 'prod' } }); // Create version (immutable snapshot) const version = apiFunction.currentVersion; // Create alias pointing to version const alias = new lambda.Alias(this, 'LiveAlias', { aliasName: 'live', version: version });
💡 Key Concept: Alias acts as a pointer that can be updated during deployment. API Gateway integrates with the alias, not the version directly.

CDK Implementation (2/3)

CloudWatch Alarm Configuration

// Create CloudWatch alarm for Lambda errors const errorAlarm = new cloudwatch.Alarm(this, 'LambdaErrorAlarm', { metric: apiFunction.metricErrors({ statistic: 'Sum', period: Duration.minutes(1) }), threshold: 5, evaluationPeriods: 2, comparisonOperator: cloudwatch.ComparisonOperator.GREATER_THAN_THRESHOLD, treatMissingData: cloudwatch.TreatMissingData.NOT_BREACHING, alarmDescription: 'Triggers rollback if Lambda errors exceed threshold' }); // Optional: Additional alarm for throttling const throttleAlarm = new cloudwatch.Alarm(this, 'LambdaThrottleAlarm', { metric: apiFunction.metricThrottles({ statistic: 'Sum', period: Duration.minutes(1) }), threshold: 10, evaluationPeriods: 2 });
⚠️ Alarm Configuration: Threshold of 5 errors over 2 consecutive 1-minute periods. Adjust based on your traffic patterns!

CDK Implementation (3/3)

CodeDeploy Setup with Rollback

// Create CodeDeploy Application const application = new codedeploy.LambdaApplication(this, 'ApiApplication'); // Create Deployment Group with Canary strategy new codedeploy.LambdaDeploymentGroup(this, 'ApiDeploymentGroup', { application: application, alias: alias, // Canary deployment configuration deploymentConfig: codedeploy.LambdaDeploymentConfig.CANARY_10PERCENT_5MINUTES, // CloudWatch alarms for monitoring alarms: [errorAlarm, throttleAlarm], // Automatic rollback configuration autoRollback: { failedDeployment: true, // Rollback on deployment failure stoppedDeployment: true, // Rollback if manually stopped deploymentInAlarm: true // Rollback when alarm triggers ⚠️ }, deploymentGroupName: 'prod-api-deployment' });
✅ Complete Setup: This configuration enables automatic rollback when the Lambda error alarm breaches during the 5-minute canary window.

Deployment Flow

What Happens During Deployment?

1️⃣ Deployment Initiated

New Lambda version published → CodeDeploy triggered

2️⃣ Phase 1: Initial Canary (T+0)

• Alias updated: 10% → New version, 90% → Old version

• CloudWatch alarms actively monitored

3️⃣ Monitoring Window (0-5 minutes)

• CodeDeploy watches specified alarms

• If alarm breaches → ROLLBACK TRIGGERED

4️⃣ Phase 2: Full Deployment (T+5)

• If no alarms → Alias updated: 100% → New version

• Deployment marked as SUCCESSFUL

5️⃣ Rollback Scenario

• Alarm triggers → Traffic immediately shifted back to old version

• Deployment marked as FAILED

• CloudWatch logs capture failure reason

Deployment Strategy Comparison

Strategy Traffic Shift Rollback Risk Best For
Canary Gradual (10% → 100%) ✅ Automatic 🟢 Low Production APIs
Linear Incremental (10% every N min) ✅ Automatic 🟢 Low Conservative rollouts
Blue/Green Instant (0% → 100%) ✅ Manual/Automatic 🟡 Medium Full environment swap
All-at-Once Immediate (100%) ❌ Manual only 🔴 High Dev/Test environments

Why Canary for Lambda?

  • Minimize blast radius (only 10% users affected initially)
  • Fast feedback loop (5 minutes validation)
  • Zero downtime during rollback
  • Works seamlessly with Lambda aliases and versions

Best Practices

✅ Do This

  • Use Multiple Alarms: Monitor errors, throttles, latency, and custom metrics
  • Set Appropriate Thresholds: Based on baseline traffic and error rates
  • Version Everything: Always publish new Lambda versions for CodeDeploy
  • Test Rollbacks: Simulate failures in non-prod to validate rollback behavior
  • Enable X-Ray: Distributed tracing helps identify issues faster
  • Immutable Versions: Never modify existing Lambda versions
  • Monitor Post-Deployment: Keep watching metrics even after successful deployment
  • Use Deployment Hooks: Add pre/post-traffic validation tests

❌ Avoid This

  • No Alarms: CodeDeploy without alarms = no automatic rollback
  • Too Aggressive Thresholds: Can cause unnecessary rollbacks
  • Too Lenient Thresholds: May not catch real issues
  • Ignoring Cold Starts: Can trigger false alarms initially
  • Single Metric Monitoring: Errors alone don't tell the full story

Common Gotchas & Pitfalls

⚠️ 1. Alarm Data Delay

CloudWatch metrics have ~1-2 minute delay. A spike might not trigger rollback immediately.

Solution: Use shorter evaluation periods or increase sensitivity.

⚠️ 2. Alias vs Version Confusion

API Gateway must point to alias, not version. Otherwise, traffic shifting won't work.

Solution: Always integrate with alias.functionArn, not version.functionArn.

⚠️ 3. TreatMissingData Setting

Default is "missing" which can cause false alarms during low traffic periods.

Solution: Set to NOT_BREACHING for most scenarios.

⚠️ 4. Cold Start Errors

Lambda cold starts during canary phase can trigger timeouts and false alarms.

Solution: Use provisioned concurrency or adjust alarm thresholds for initial deployment phase.

⚠️ 5. IAM Permissions

CodeDeploy needs permissions to update Lambda aliases and read CloudWatch alarms.

Solution: CDK handles this automatically, but verify if using custom roles.
